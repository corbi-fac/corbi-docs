Checked Builds

An architect builds and refines a simple massing in Blender by chat. Corbi checks what it built, every run ends cleanly, and any answer can be reopened later. This release adds the Sensors and Termination boxes, which completes the course's harness diagram.

Starting point

What already works, so no story repeats it

  • A prompt builds in Blender: the model reads the scene and runs bpy code in a loop until it answers
  • Each run sends the whole session chat back to the model, including earlier tool calls
  • A Blender error comes back to the model as a failed tool result
  • Every answer saves a .blend copy and a models row while Blender is open
  • Steps show live as compact lines, apart from markdown answers
  • Projects are created and loaded with the chat of their last-touched session
  • The LLM is picked from Anthropic or Gemini, depending on which keys are set
  • Blender is detected and launched, and its add-on is installed, from the app

Each story below opens with a Today line: what happens now and the gap the story closes.

Stories in full

Acceptance criteria are the contract

Each criterion is tagged with how it's proved, using the methods in AGENTS.md: app is a logged manual Blender run, unit is a test with the scripted model and a recorded scene, and api, db, browser, cli and code are as listed there. Nothing in a test needs a running Blender or a live LLM.

Shape it by chat 3 days · Context · Agent loop

A11 dayfrom #85

Every run starts from the current scene

Before each prompt, Corbi reads what's in Blender and gives it to the model, so a follow-up edits what's there instead of building a second copy.

Today Follow-ups can already work: the whole chat goes back to the model, and it can call get_scene_info. Nothing makes it look first, so it may add a second building instead of editing the first.

Requirements

Scene known
Each run starts with a short summary of the scene's objects (name, size, position) in the model's context

Not included

  • Undoing a change (D3 covers going back)

Acceptance criteria

  1. The model's input for a run includes a summary of the scene's objectsunit
  2. After "a 4-storey block, 20 by 12 metres", the follow-up "make it 6 storeys" leaves one object, now 6 storeys tallapp
  3. With Blender closed, a follow-up still gets an answer, without a scene summaryunit

Shares the scene reader with B1

A21 daynew

Refer to each building by name

Each building Corbi makes has a readable name, so the architect can say "make the tower taller" and only the tower changes.

Today get_scene_info already returns object names, but nothing asks the model to name what it builds, so objects get Blender defaults such as Cube.001.

Requirements

Naming
The system prompt tells the model to name every object it creates by its role, such as "Tower" or "Block A"
Summary
A1's scene summary lists objects by name

Acceptance criteria

  1. Objects created in a run have readable names, not Blender defaults such as "Cube.001"app
  2. With a tower and a podium in the scene, "make the tower 10 storeys" changes only the towerapp
  3. The system prompt carries the naming rulecode

Depends on A1

A31 dayfrom #86

Talk an idea through without touching Blender

An architect can discuss an idea with Corbi before anything changes in Blender, then ask it to build what they agreed.

Today The model only has no tools when Blender is closed. With Blender open there's no way to talk without it acting, and every run saves a file even when nothing changed.

Requirements

Switch
"Discuss only" next to the prompt box. While it's on, the run gets no tools
Memory
The discussion stays in the chat, so a later build prompt can refer to it

Acceptance criteria

  1. With the switch on, the run's tool list is empty and the scene is unchangedapi
  2. With the switch off, "build what we discussed" builds itapp
  3. A discuss-only answer makes no savedb

Check what was built 3 days · Sensors

B11.5 daysnew

Corbi checks every change it makes and fixes its own mistakes

After every change Corbi makes in Blender, it reads the scene back and checks the result. It notices its own mistakes and fixes them before it answers.

Today A bpy error already comes back to the model as a failed tool result. Code that runs without error but builds the wrong thing is never checked.

Requirements

When
After each tool call that changes the scene
Checks
Blender reported no error; every new object has volume; nothing is below ground; no side is longer than the size limit
Result
A check report in the model's context before its next turn

Not included

  • Checks against a site boundary, which needs sites (later)

Acceptance criteria

  1. After a scene-changing tool call, the checks run before the model's next turnunit
  2. An object below ground or with no volume fails, and the model's next turn sees the reportunit
  3. A change that passes every check adds nothing to the model's contextunit
  4. The checks run in tests against a recorded scene, without Blender or a live LLMcli

Shares the scene reader with A1 · Blocked on check thresholds; the decision on Blender code

B21 daynew

Answers quote the figures measured in Blender

Corbi's answers give the height, footprint and floor area measured from the geometry, not figures the model came up with.

Today Nothing is measured. Any height or area in an answer is the model's own claim.

Requirements

Measured
Per object: height, footprint area, storeys from the floor-to-floor height, gross floor area
Where
Added to the check report at the end of a run. The system prompt tells the model to quote them

Acceptance criteria

  1. For a 20 × 12 m, 14 m tall block, the report gives 240 m² footprint and 4 storeys at 3.5 munit
  2. The final answer quotes the measured figuresapp
  3. The measurement runs in tests without Blendercli

Depends on B1 · Blocked on floor-to-floor height

Finish a run cleanly 3 days · Termination

C11 daynew

Every run ends within a step and time limit, and says why

A run can't loop forever. When it stops early, the architect is told why and loses nothing.

Today The only cap is LangGraph's default recursion limit of 10,007 steps, which in practice means no limit. There's no time limit, and every run reports completed.

Requirements

Limits
A step limit in model turns and a time limit in seconds
Reasons
completed, step_limit, timeout
Early stop
The scene is still saved and the chat still stored

Acceptance criteria

  1. A scripted model that always asks for a tool stops at the step limit with reason step_limitunit
  2. A run past the time limit stops with reason timeoutunit
  3. After an early stop, the chat rows and the save are writtendb
  4. A run whose model answers without tool calls ends with completed, as it does nowunit
  5. POST /agent/run returns the reason, and the chat says why when it isn't completedapi

Blocked on limit figures

C21.5 daysnew

Stop a run that is going the wrong way

The architect doesn't have to wait for a run they can already see is wrong.

Today A run can't be interrupted. Closing the tab doesn't stop it: the run carries on on the server.

Requirements

Control
A Stop button while a run is going
Result
The run ends within a few seconds with reason cancelled, and keeps what it had done

Acceptance criteria

  1. Pressing Stop ends the run with reason cancelledbrowser
  2. The chat up to the stop is stored and the scene is saveddb
  3. The next prompt runs normallybrowser

Depends on C1

C30.5 daynew

Corbi stops and asks when the same check keeps failing

If Corbi can't fix something, it asks the architect what to do instead of using up the step limit.

Today A run that keeps failing carries on until the model gives up or something errors.

Acceptance criteria

  1. The same check failing on three turns in a row ends the run with reason stuckunit
  2. The answer names the failing check and asks how to proceedunit
  3. A check that fails once and then passes doesn't stop the rununit

Depends on C1, B1

Come back to my work 3 days · Memory · saves

D11 dayfrom #87

See a save after every answer that changed Blender

Each answer that built something shows its save in the chat, so the architect can see their history and pick a point to go back to.

Today Every answer already saves a .blend and a models row. The chat doesn't show them, there's no endpoint to list a session's saves, and each save is stamped before its own turn's messages.

Requirements

Order
A run's chat rows are written before its save, so a save's time comes at or after every message of its turn
List
GET /sessions/{id}/models, oldest first
In the chat
A save marker after each answer that saved

Acceptance criteria

  1. In a run, every chat row's created_at is at or before its save'sdb
  2. GET /sessions/{id}/models lists the saves oldest firstapi
  3. Each answer that saved shows a save marker, including after a project is reloadedbrowser
D20.5 dayfrom #87

Opening a project puts its latest save back in Blender

The architect carries on where they stopped, with the model they left.

Today Loading a project brings back its chat but not its model: Blender keeps whatever it already had open.

Requirements

Open
The API asks Blender to open the latest save's file
Tools
Opening a file is called by the API and isn't offered to the model

Acceptance criteria

  1. Loading a project opens its session's latest save in Blenderapp
  2. The model's tool list has no file-opening toolcode
  3. With Blender closed, the project still loads and the chat says the file wasn't openedbrowser

Depends on D1
